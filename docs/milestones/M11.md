## 1. Goal
1. **VirtIO-GPU Display Driver:** Implement a 2D VirtIO GPU driver (`virtio-gpu-pci`, Vendor 0x1AF4, Device 0x1050 / legacy 0x1010) supporting 2D resource creation (`B8G8R8A8_UNORM`), backing page attachment, host transfer, scanout binding, and resource flushes, integrated seamlessly with the software compositor as a primary or fallback display target alongside UEFI GOP.
2. **System Clipboard Service:** Deliver a secure, cross-process clipboard daemon with typed MIME formats (`text/plain`, `text/uri-list`, `image/x-raw`), monotonic sequence numbering, ownership arbitration, and capability-guarded Ring 3 syscalls (`sys_clipboard_write`, `sys_clipboard_read`).
3. **Desktop Drag-and-Drop (DND) Subsystem:** Provide an interactive DND engine supporting drag source detection, visual translucent drag-ghost rendering, target drop-zone hit-testing, payload transfer (files, text, window tabs), and cancel/commit lifecycle.

---

## 2. Non-Goals
- 3D hardware acceleration via Virgl3D or Vulkan/Venus (M11 is strictly 2D display and scanout).
- Multi-head display across multiple physical monitors (scanout 0 only).
- OLE/COM clipboard abstractions (pure POSIX / NovaOS capability IPC).
- Remote network clipboard sharing.

## 8. Security Checks (CONTRACT.md Section 13A)
- **Ring 3 Syscall Pointer Validation:** `sys_clipboard_write` and `sys_clipboard_read` validate all userland buffers via `validate_user_buffer` to prevent kernel tampering and user memory fault injection.
- **Payload Clamping:** Hard buffer clamp of 64 KiB on clipboard data prevents kernel heap exhaustion.
- **Capability Enforcement:** Process requires `CAP_CLIPBOARD` or standard userland authorization to access clipboard data.
- **VirtIO Boundary Isolation:** Physical page descriptors passed to host virtqueue are bounded to verified framebuffer frames.
